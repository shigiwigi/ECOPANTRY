# Contributing to EcoPantry

Thanks for contributing.

## Workflow
1. Create a branch for your work.
2. Keep changes focused on one module or phase.
3. Follow the existing UI design system and code conventions.
4. Never commit `.env` files, passwords, API keys, device credentials, or private data.
5. Test the affected frontend, backend, or firmware before opening a pull request.
6. Update README or documentation when setup, APIs, hardware wiring, or behavior changes.

## Suggested branch names
- `feature/inventory-management`
- `feature/esp32-sensor-api`
- `fix/mobile-navigation`
- `docs/hardware-wiring`

## Pull request checklist
- [ ] Changes are limited to the intended scope.
- [ ] Existing functionality is preserved.
- [ ] Desktop and mobile layouts are checked when UI changes are made.
- [ ] Tests/build checks pass.
- [ ] No secrets or private data are included.
- [ ] Documentation is updated where necessary.
